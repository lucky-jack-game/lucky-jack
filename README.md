# LUCKY JACK

ライフを賭けて読み合う、1対1のカードゲーム。ブラウザだけで遊べる。

**遊ぶ：** https://lucky-jack-game.github.io/lucky-jack/

PC（横画面）とスマートフォン（縦画面）の画面幅に対応している。動作確認は Chromium で 1280px 幅と 390px 幅の両方で行っている。

## どんなゲームか

札の強さだけでは勝てず、「相手に見えている情報」と「賭け方」で読み合う、独自ルールのカードゲーム。

- お互いライフを持つ。相手のライフを 0 にするか、最終局で多く残した方が勝ち。
- 札は I〜X。大きい方が勝つ。ただし **I だけは X と Queen に勝つ**。Queen は I 以外に必ず勝ち、1試合に1枚だけ出る。
- 手札は2枚、1局に出すのは1枚。相手に見えるのは **UP（VI〜X）と DOWN（I〜V と Queen）の枚数だけ**。
- 局の初めに片方が **KING**（札で勝った方がライフを取る）か **JOKER**（札で負けた方が取る）を宣言する。
- 札を伏せたまま賭け合う。降りれば、賭けた分は相手に渡る。

初めて開くと「ルール説明（9枚）」→「実践チュートリアル（台本付きの4局）」が順に流れ、そのまま CPU との対戦に入れる。

### 操作

マウスまたはタップ。キーボードでも遊べる（KING / JOKER は `A` / `D`、賭けは `A` `S` `D` `F`。設定で変更できる）。キーでの「降りる」は誤操作を防ぐため長押し。

## 工夫したところ

- **ルールの本体は1箇所だけ。** 1試合の進行は `shared/match.js` の状態機械（通信もタイマーも持たない純粋な関数群）で、CPU対戦・実践チュートリアル・経済シミュレータ・オンライン対戦サーバーがすべて同じコードを通る。
- **数値はシミュレーションで決めた。** `npm run sim` で2万試合を回し、決着までの局数・逆転率・1局で終わる試合の割合などを測って調整した。例：最終局だけ最初の賭け（アンティ）を 1 → 3 にしている。1のままだと、最終局に入る時点で勝敗が決まっている試合が 73% あった。
- **3Dの卓は必要な画面でだけ読み込む。** three.js は対戦画面とホームの卓でしか使わないので `React.lazy` で分け、最初の表示を軽くしている。3D が使えない端末では2Dの卓に切り替わる。
- **音はすべて Web Audio API で合成。** 音声ファイルは1つも無い。
- **進捗はブラウザの localStorage に保存。** アカウントもサーバーも要らない（戦績・実績・CHIP・ショップ・スキン）。

## 提出版の範囲

遊べるのは CPU との対戦。オンライン対戦（Node.js + Socket.io、`server/`）も実装してあるが、GitHub Pages にはサーバーを置けないため入口を閉じている（`client/src/features.js` の `ONLINE_ENABLED`）。

## フォルダ構成

```
shared/            ルール本体（札の比較・カードの山・賭けの上限・CPUの判断）と1試合の進行
client/            画面（React + Vite）
  src/App.jsx      アプリの外枠（タブの切り替え・ヘッダー・ナビ）
  src/screens/     キャリア・実績・スキン・ショップ・設定・ルール説明・遊び方・タイトル
  src/battle/      対戦画面・CPU対戦・実践チュートリアル・戦績の集計
  src/three/       3Dの卓・カード・賭けたライフ
  src/audio/       効果音とBGM（Web Audio API で合成）
  public/          カードの絵
server/            オンライン対戦のサーバー（提出版では使っていない）
tools/             経済シミュレータ
.github/workflows/ テスト・ビルド・GitHub Pages への公開
```

## 動かし方

Node.js 22 以上（GitHub Actions は 24 で動かしている）。

```sh
npm install --prefix client
npm run dev --prefix client     # http://localhost:5173
npm run build --prefix client   # client/dist に出力
```

テスト（ルール・進行・報酬・実績・ショップなど 124 件）：

```sh
npm install --prefix server
npm test
```

`master` へ push すると、GitHub Actions がテスト → ビルド → GitHub Pages への公開を行う（`.github/workflows/deploy.yml`）。

## 制作ノート

### 賭けジャンケンから始まった

最初は名前のとおり「賭けジャンケン」だった。遊べる形にしようと足していくうちに、16人トーナメント、デッキ編成、3種類の通貨、勝ち抜きの大技まで膨らんだ。

作り込むほど、審査で数分触るだけでは面白くなる前に終わるゲームになっていた。1回遊ぶのに13局かかり、いちばんの見せ場に出会えるのは12〜16%。そこで全部やめて、**1対1で1枚を賭けて読み合う**形に絞り直した。

### ルールで残したもの

- **相手に見えるのは UP / DOWN の枚数だけ。** Queen と I をあえて DOWN に入れた。UP は正直な信号、DOWN は「最弱かもしれないし最強かもしれない」信号になり、読み合いは必ず DOWN の側で起きる。
- **手札2枚から1枚を選ぶ。** 前の版は配られた1枚に賭けるだけで、ブラフが根拠のない度胸試しにしかならなかった。
- **引き分けは作らない。** 同じ数字は宣言した側の勝ち。
- **札は120枚作って半分を捨ててから配る。** 残りの枚数を数えれば勝てる、という遊び方を生まないため。

### 数字は勘で決めなかった

CPU 同士の試合を2万回ずつ回して決めた。

- 1局目で決着する試合が 12.6% あった。1局に賭けられる上限を「開始ライフ − 1」にして 0% にした。
- 最終局に入る時点で勝敗が決まっている試合が 73% あった。最終局だけアンティを 3 にした（1段ずつ上げる案なども測ったが、これが一番よかった）。
- Queen を素直に混ぜると、登場するのは 43% の試合だけだった。山に入れる位置を絞って 90% にしつつ、出る時期は読めない幅に留めた。

### 見た目

- **ネオンのカジノをやめて、リゾートホテルの大ホールにした。** ホームの部屋は画像を使わず、CSS で一点透視の箱として組んでいる。奥の卓は対戦で使う卓そのもので、スキンを替えるとホームの卓も替わる。
- **画面に操作の説明文を置かない。** 押せる物が出ていれば伝わる。言葉にするのは「相手が降りた」のように、見ているだけでは分からない事実だけ。
- **数字の書体は「1 と 7 を見間違えない」ことで選んだ。** 小さな枠に数字だけが入る場面が多いため。

### 削ったもの

- **オンライン対戦は、サーバーまで作ったうえで入口を閉じた。** GitHub Pages にはサーバーを置けないし、審査で遊ぶのは1人なので。
- **いない相手を作らない。** オンラインの空席を CPU で埋めることも、他のプレイヤーのランキングを出すこともしない。記録はすべて自分の分だけ。
